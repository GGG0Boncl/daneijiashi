# 大内家事 App（Android）+ 局域网同步中枢 —— 方案 v0.1

> 目标：家人每天用手机记录小目标、打卡；**不需要任何第三方推送/云服务**；回家连上同一 WiFi 后自动同步到家里的 Windows 台式机；台式机上跑 dsh，负责复盘定性分析。

## 1. 为什么是"本地 App + 局域网"这条路

- 微信/QQ 没有可用的个人推送接口；飞书单聊通道当前不可用（230101）。
- 手机自己就能当闹钟：07:30 / 21:30 用**系统本地通知**触发，断网、没开电脑都照常响。→ 推送需求被彻底消掉。
- 数据只在自家局域网里流动，不经过任何第三方服务器；离线也能完整记录一整天。
- 家里的 Windows 机器当"中枢"，数据落在 `family-checkin/data/`，与现有 `checkin.mjs` 完全同一套 schema，dsh 分析零改造成本。

## 2. 架构

```
┌─────────────────────────┐         ┌──────────────────────────────┐
│  Android App（每人装一份）│         │  Windows 台式机（家里中枢）     │
│  · 今日目标/打卡/备注     │  局域网  │  · hub.mjs  HTTP :8787        │
│  · 本地存储 IndexedDB    │◀───────▶│  · UDP 广播 :8788（自动发现）  │
│  · 07:30 / 21:30 本地通知 │  WiFi   │  · 数据落 data/records/<人>/  │
│  · 历史 + 简易统计        │         │  · 网页看板（浏览器打开）      │
└─────────────────────────┘         │  · dsh web :3080（聊天+分析）  │
                                    └──────────────────────────────┘
```

- **App 是唯一录入端**，离线优先：所有操作立刻写本地，联网与否不影响使用。
- **中枢只管收与合**：合并规则确定、可回溯，不做"覆盖式"清理。
- **dsh 只读数据写分析**：`checkin.mjs report` → 定性复盘，一个人一份，不混。

## 3. 数据与同步

沿用现有 schema（`memberId / date / version / goals[{id,text,status,checkedAt,note}]`），只加三个同步字段：

| 字段 | 用途 |
| --- | --- |
| `updatedAt` | 每条目标/每份记录的最后修改时间（ISO，北京时间） |
| `deleted` | 软删除墓碑，防止删掉的目标被另一台设备"复活" |
| `deviceId` | 哪台设备最后写的，便于排查 |

同步流程：

1. App 联网时 `GET /api/health` 探测中枢（预先 UDP 广播发现 IP，避免手填）。
2. `POST /api/sync` 带 `since` 时间戳 → 中枢返回双向差异。
3. 合并按 **目标为最小单位、`updatedAt` 晚者胜**；同一天的记录整体 `version` 取大者，不丢条目。
4. 中枢落盘 + 追加一行同步日志，App 侧更新 `lastSyncAt`。

触发时机（按可靠性排序）：
- App 打开 / 从后台切回前台 → 立即同步（第一版就有）
- 连上家庭 WiFi（NetworkCallback）→ 触发一次后台同步（原生小模块，第二版）
- 兜底：每隔 15 分钟 WorkManager 试一次（省电，不强求）

## 4. 提醒（手机本地，核心体验）

| 时间 | 条件 | 文案 |
| --- | --- | --- |
| 07:30 | 当天还没有目标 | "早上好呀～ 请设置你今天的工作/学习/生活小目标" |
| 21:30 | 当天有目标，且存在「未打卡」 | "你今日的目标还没有完成打卡，请及时打卡"，并列出待打卡项 |

- 完全离线判断，不依赖中枢是否开机。
- Android 13+ 需要通知权限，Android 12+ 精确闹钟需要 `SCHEDULE_EXACT_ALARM`，首次启动引导授权，缺权限时退化为"大致准时"并提示。
- 21:30 之后入口不关闭，随时可补打卡。

## 5. 技术栈（推荐）

| 层 | 选择 | 理由 |
| --- | --- | --- |
| App 外壳 | **Capacitor 6**（WebView 套壳，出 APK） | UI 用 HTML/CSS/JS，同一套页面在电脑浏览器也能直接看；改样式不用重新学 Android |
| UI | 原生 HTML + CSS + 少量 JS（无框架） | 页面简单，体积小，出问题好定位 |
| 本地存储 | IndexedDB | 数据量极小（每天几条），不需要 SQLite 插件 |
| 通知 | `@capacitor/local-notifications`（底层是系统 AlarmManager） | 原生每日通知，App 关了也会响 |
| 构建 | JDK 17（已有）+ Android SDK（放 `K:\dshworkspace\android-sdk`）+ Gradle（走腾讯镜像） | 本机 C 盘只剩 5GB，必须装 K/E 盘；services.gradle.org 被墙，用镜像 |
| 中枢 | Node 22 + 原生 `http`/`dgram` + 复用 `checkin.mjs` | 零依赖，和现有数据层同源 |

备选：**Kotlin + Jetpack Compose 原生**（体验更好、包更小，但代码量约 2 倍，且我这边没有模拟器可验证 UI，踩坑概率高）。

## 6. 阶段与验收

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| P0 | 装 Android SDK + 构建工具链，跑通一个空白 APK | `gradlew assembleDebug` 出 APK，装上能启动 |
| P1 | App 主功能：今日目标增删改、三态打卡、备注、历史 | 手机上断网完成一天完整操作，杀进程重开数据还在 |
| P2 | 本地通知 07:30 / 21:30 | 设一台测试机，两个时间点都能准时收到，且 21:30 不该响时绝不响 |
| P3 | Windows 中枢：发现 + 同步 API + 落盘 + 看板 | 手机改数据 → 回家连 WiFi → 电脑 `data/records/` 出现一致记录 |
| P4 | dsh 接入分析 + 家庭互看开关 + 导出备份 | 说"帮我分析最近 7 天"，dsh 直接读中枢数据出定性复盘 |

## 7. 已知风险

1. **我没法在模拟器里点 UI**（不装模拟器省 2GB+）：UI 的最终验收得靠你在手机上试，报错请**复制文字**给我（我默认模型看不了截图，看图要换视觉模型）。
2. `dl.google.com` 在本机 curl 走 schannel 会失败，但 **Node fetch 可用**（已实测 206），所以 SDK 用 Node 下载脚本装。
3. `services.gradle.org` 不可达 → Gradle 用腾讯镜像，Maven 用阿里云镜像；万一大包拉不下来，退手动下载 + 本地仓库。
4. WebView 后台节流：App 不在前台时 JS 会被挂起，所以"到家自动同步"必须靠一个小原生模块兜住，不能纯靠网页逻辑。
5. 侧载 APK 需要家人手机允许"安装未知来源应用"；每台手机首次启动填一次自己的名字。
