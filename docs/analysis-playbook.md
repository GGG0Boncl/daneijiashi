# 复盘怎么做（Agent 操作手册）

> 触发语：**"帮我分析一下我的目标情况" / "复盘最近打卡" / "看看中长期执行情况"**。
> 一次只分析一个人，一份报告只属于一个人。

## 1. 取数（三条命令，按需选）

```bat
REM 短期：近 7 天（也可以 3 天）
node tools\analyze.mjs <成员ID> --days 7

REM 中长期：近 30 天 / 一个季度
node tools\analyze.mjs <成员ID> --days 30

REM 需要原始结构自己算（含 details / notes / stats / contrast）
node tools\analyze.mjs <成员ID> --days 14 --json > pack.json
```

数据来源就是中枢落盘的 `data/records/<成员ID>/<日期>.json`，
和手机同步过来的是同一份，所以**手机上记的东西，回家同步后立刻能分析**。

也可以直接查原始记录：`node checkin.mjs query <成员ID> --from A --to B`。

## 2. 素材包里哪些东西值得用

| 素材 | 怎么用 |
| --- | --- |
| 提交率 / 完成率 | 只做"背景板"，一句话带过，别当主角 |
| `轻量日 vs 重量日` 的完成率差 | 差 >15% 就可以说"目标一多就崩"，这是最常见的真话 |
| `反复卡住的目标` | 直接点出来：这类目标要么拆小、要么换形式、要么先放下 |
| `22:00 后打卡次数` | 说明"结算时间是睡前"，可以往前提 |
| 按星期的最低完成率 | 找"最累的那一天"，而不是喊"要更自律" |
| `前后半程趋势` | 中长期才有的信号，用来判断"习惯在长出来还是在断" |
| `备注原话` | **最有价值**：引用 1~2 句本人说过的话，比任何百分比都动人 |

## 3. 输出结构（固定三段，别加第四段）

**① 现状复盘总结**
用两三句话讲清"这段时间你实际是怎么过的"：提交得稳不稳、量大概多少、哪些是真做到的。
像聊天，不像汇报。

**② 识别到的问题**
挑 2~4 个**具体**的问题，每个都带证据（哪天、哪条目标、哪句备注）。
常见类型：目标太多 / 难度太高 / 类型不合适（需要连续专注的排在深夜）/ 时间安排不对 / 习惯断层 / 只打卡不记录。

**③ 温和、能落地的调整建议**
给 2~3 条**明天就能试**的小改动，越小越好，例如：
- 每天最多写 3 条，第 4 条留到有空再加
- 把练字从"每天半小时"改成"隔天 10 分钟"，先让它能完成一次
- 打卡时间从睡前 22:00 挪到晚饭后，别让"结算"变成压力峰值
- 每周留一天不设目标，允许断，断了才接得上

## 4. 反模式（写之前自查）

- ❌ 通篇表格和百分比，没有一句人话
- ❌ "执行力不足""自律性差""拖延症"这类考评词
- ❌ 把两个成员放在一起比
- ❌ 建议一次给五条十条（等于没给）
- ❌ 编造数据里没有的结论（没记录就写"这几天没有记录，先不判断"）
- ❌ 替成员改目标或打卡状态（只提建议，改不改由本人决定）

## 5. 写完自检三问

1. 有没有引用至少一句本人备注原话？
2. 建议是不是"明天就能做"的粒度？
3. 语气像不像家里人说话（而不是绩效面谈）？
